# Global Memory

这个技能用于继续之前的话题、回忆用户偏好、查找旧聊天记录，以及在新会话里找回之前的上下文。

## Tool

- `MemoryOperation`: 读写用户长期记忆，获取和搜索历史聊天归档。

## Workflow

1. 只要用户明确透露了以后可能有用的稳定信息，就主动调用 `MemoryOperation` 记录，不必等用户明确说“记住”。兴趣偏好、身份习惯、重要经历、长期计划、正在做的事情、人际关系，以及对某人的稳定评价都属于可记录信息。
2. 日常写入使用 `operation=append` + `dataType=user`，只提交本轮新增的详细记录。服务端会自动添加记录时间并追加到旧记忆，不要为了简短而用 `set` 重写旧内容。
3. 记录要写清发言者昵称或ID、说过的内容、涉及对象和必要上下文，尽量保留原话中的人物、事件、原因、时间线、程度和条件，不要压缩成几个标签。
4. 第三方评价按用户的主观看法记录，例如“用户小明(10001)说过：他认为张三很可靠”，不要把它改写成客观事实。
5. 如果用户提到“之前”“上次”“刚才”“还记得吗”“我们聊过”“你说过”等延续性表述，先检查系统自动注入的“系统预检索记忆”。
6. 如果自动注入的记忆还不够，调用 `MemoryOperation`：
   - 获取用户长期记忆：`operation=get` + `dataType=user`
   - 获取历史归档列表：`operation=get` + `dataType=chatHistory`
   - 搜索相关历史：`operation=get` + `dataType=chatHistory` + `data=search:关键词`
   - 读取某条归档详情：`operation=get` + `dataType=chatHistory` + `data=guid:id`
7. 先根据搜索结果锁定最相关的归档，再读取详情，不要一上来遍历所有历史。
8. 回答时优先引用与当前问题直接相关的记忆；如果历史记忆与用户当前说法冲突，以用户当前说法为准。

## Rules

- 在说“我不记得”“之前没聊过”“没有这段历史”之前，先看系统自动检索到的记忆，必要时再调用 `MemoryOperation` 搜索。
- 不要把不确定的历史记忆说成确定事实；如果记忆片段不完整，应明确说明是“根据历史归档看起来像是”。
- 搜索历史时优先提取主题词、项目名、命令名、文件名、报错文本等高信息量关键词。
- 用户要求开始全新话题时，不要强行引用旧记忆；只有在确实相关时才使用。
- 不要记录密码、验证码、访问令牌、私钥等秘密，也不要记录一次性指令、短暂情绪、玩笑或未经用户明确表达的推测。
