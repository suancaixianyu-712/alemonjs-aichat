# 咸鱼扫雷

本技能只使用 `XianyuGame` 返回的可见棋盘。不得读取文件、日志、执行指令，也不得尝试获取 `isMine`、隐藏格数字或完整雷区答案。

## 棋盘与坐标

- 先调用 `XianyuGame` 的 `minesweeper_snapshot`；若当前会话还没有对局，快照会返回 `null`，此时按“开始并接管一局”用 `minesweeper_start` 开局，并直接使用它返回的 `snapshot`。
- 坐标为“字母列 + 数字行”，例如 `A0`。字母从左到右，数字从上到下，均以快照的 `coordinateSystem` 为准。
- 二维数组按 `board[y][x]` 读取：外层是从上到下的数字行，内层是从左到右的字母列。例如 `A0` 是 `board[0][0]`，`B3` 是 `board[3][1]`。
- 格子值只有：`unknown`、`flag`、以及已翻开的数字 `0` 到 `8`。

## 开始并接管一局

当用户要求开始、重开扫雷，或要求你完整玩一局时：

1. 调用 `XianyuGame`，`action` 为 `minesweeper_start`，并由你自己选择 `difficulty`：`简单`（9×9，10 雷）、`中等`（16×16，40 雷）、`困难`（25×25，99 雷）。用户没指定时用 `简单`；用户说了难度就按用户的。不要为了难度反问用户，直接开始并在回复里说明选了哪个难度。
2. 若返回 `alreadyRunning` 为 `true`，说明当前会话已有进行中的对局，插件会直接返回该棋盘且不会重开，不要再调用 `minesweeper_start` 试图覆盖，直接接手操作返回的 `snapshot`。
3. 若返回 `ok` 为 `false` 且说明对局属于其他成员，不要抢占，先向用户说明，由用户决定是否结束该对局。
4. 开始后按下面的“自动游玩”持续操作，直到 `status` 变为 `win` 或 `lose`。

## 自动游玩

仅当用户明确要求 Aichat 操作、接管或自动玩扫雷，或你已经用 `minesweeper_start` 开局时，才允许调用修改棋盘的动作。用户只是询问建议时不得改棋盘。

1. 对每个已翻开数字格，统计相邻的 `flag` 和 `unknown`。
2. 若“数字 - 相邻旗标数 = 0”，相邻的全部未知格确定安全，可用一次 `minesweeper_open` 批量翻开。
3. 若“数字 - 相邻旗标数 = 相邻未知格数”，相邻未知格确定是雷，可用一次 `minesweeper_mark` 批量标记。
4. 应合并来自多个数字格的确定操作并去重；每次操作后都以工具返回的新快照重新计算，不能沿用旧棋盘假设。
5. 若发现旗标与可见数字矛盾，使用 `minesweeper_unmark` 撤销能确定错误的旗标，再继续推理。
6. 当没有确定操作时，按所有相邻约束估计风险，选择估计雷概率最低的未知格翻开；优先选择能揭示更多区域的格子。开局无数字信息时优先翻开靠近中心的一格。
7. 持续调用快照和操作，直到返回的 `status` 为 `win` 或 `lose`；不能在 `playing` 状态下只解释或提前结束。

可以批量操作，但同一批 `minesweeper_open` 中只能包含根据同一份当前快照已经确定安全的格子。猜测时每次只翻开一个格子，看到新快照后再继续。

每次操作结果的 `progress` 会给出 `openedDelta`、`flagDelta`、累计翻开数和状态。下一次工具调用前，用一句简短的公开进度说明上一轮结果和本轮动作，例如“第 3 步：刚才新增翻开 6 格；现在标记 B4、C4”。不要输出长篇推理，也不要逐格刷屏。结束时说明胜利或踩雷。

## 中途建议

普通聊天中，用户询问当前扫雷局面或下一步建议时：

1. 只调用 `minesweeper_snapshot`。
2. 说明确定安全格、确定雷格和推理依据；没有确定解时，明确说这是概率建议。
3. 不调用 `minesweeper_start`、`minesweeper_open`、`minesweeper_mark` 或 `minesweeper_unmark`，由用户自行操作。

## 结束对局

1. 用户要求结束、退出或放弃当前扫雷时，调用 `XianyuGame`，`action` 为 `minesweeper_exit`，并简短告知对局已结束；返回 `ended` 为 `false` 时说明当前没有进行中的对局。
2. 你判断这局已经无法继续时（剩余未知格之间没有任何确定约束，只能逐格瞎猜，且用户没有要求继续猜），可以直接结束并说明原因；否则按“自动游玩”继续推理。
