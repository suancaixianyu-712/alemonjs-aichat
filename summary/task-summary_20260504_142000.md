# 任务摘要

## 任务1: 修复正则触发被主动搭话开关覆盖的问题

### 问题描述
用户反馈：关闭主动搭话、开启仅艾特回复后，正则规则匹配了，但还是只有艾特才回复。

### 问题原因
在 `getChatConfig.ts` 的 `shouldSkipAIReply` 函数中，**没有检查 `regexTriggered` 标记**。导致正则触发时，仍然会被主动搭话检查和概率过滤覆盖。

### 解决方案
修改 `src/response/zreply/getChatConfig.ts`，在 `shouldSkipAIReply` 函数开头添加正则触发检查：

```typescript
// 正则触发时直接必定回复，忽略后续所有判断
if (e["regexTriggered"]) {
  console.log("正则规则匹配, 跳过 shouldSkipAIReply 检查, 必定回复");
  return false;
}
```

### 修改文件
- `src/response/zreply/getChatConfig.ts` - 第 239 行附近

## 任务2: 添加 Redis Unix Socket 自动检测

### 需求
让软件在启动时检查 Redis Unix Socket 是否可用，如果可用且配置文件没有配置数据库 IP，则使用 Unix Socket 访问数据库。

### 实现方案
1. 在启动时检测常见 Unix Socket 路径
2. **配置文件 host 为空时**，自动切换到 Unix Socket 连接
3. 配置了 host 则使用 TCP 连接
4. 日志输出当前使用的连接方式

### 检测的 Socket 路径
- `/var/run/redis/redis-server.sock`
- `/run/redis/redis-server.sock`
- `/tmp/redis.sock`
- `/var/run/redis/redis.sock`

### 修改文件
1. **`src/config.ts`**
   - 添加 `detectRedisSocket()` 函数
   - 添加 `createRedisConnection()` 函数
   - 修改 `db` 类构造函数使用自动检测逻辑

2. **`src/redis.ts`**
   - 添加相同的 Socket 检测逻辑
   - 使用 `createRedisConnection()` 创建 Redis 实例

### 启动时日志输出
- `[Redis] 当前连接方式: Unix Socket (/path/to/socket)`
- 或 `[Redis] 当前连接方式: TCP (host:port)`
- 或 `[Redis] 当前连接方式: TCP (localhost:6379)`
